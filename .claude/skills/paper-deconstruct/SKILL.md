# Paper Deconstruct：重走研究路线并找出问题

读一篇论文最有价值的地方，不是它的结论本身，而是作者在每个分叉口做了什么选择、这些选择让结论在什么条件下成立、以及哪些东西其实没有被证明。这个 skill 把精读拆成三层：**重走路线**（理解作者为什么这么做）、**核对证据**（判断结论能信到什么程度）、**落到下一步**（读者能借什么、要避开什么、还能问什么）。找问题贯穿前两层：第一层找"路线断点"，第二层找"证据缺口"，最后有一轮自我反驳，把站不住的批评删掉。

默认用中文写报告，论文原文、指标名、图表编号保留英文。

## 第 0 步：先登记读到了什么

在下任何判断之前，记录实际读取的材料：全文还是只有摘要，正文哪些节，哪些图表真的看过（看图本身，还是只看了图注），补充材料、代码和数据是否可得。把它写在报告开头的"阅读范围"里。

这一步决定了后面能说什么。只读了摘要，就只能复述作者主张，不能评价方法；没看到某张图，就不能说"图 3 支持/不支持"；说"作者没有处理 X"之前，要写明查过哪些节（例如"Methods、Discussion、Limitations、Supplement S2 中均未见"），查不全就写"在已读部分未见"。书目信息核实了不等于读过全文。拿不到全文时如实说明，并建议用户提供 PDF，而不是凭摘要和记忆补全。

然后判断论文类型（方法开发、验证/一致性研究、诊断准确性、预后/队列、干预试验、仿真/体模、综述等）。不同类型用不同的尺子，不拿一把尺子量所有论文。读 `references/study_type_rulers.md` 选出这篇论文该用的核心检查项和对应报告规范。如果论文属于心脏影像运动/应变、配准或运动估计，同时读 `references/cardiac_motion_strain.md`。

## 第一层：重走研究路线

先用三五句话写出作者自己的结论，各附原文位置。这样后面所有的拆解都有一个明确的对照目标，也避免一上来就用自己的理解替换作者的主张。

然后按顺序重建路线：作者认为领域已经知道什么 → 指出的缺口 → 提出的假设或目标 → 为检验它选的研究设计 → 数据（来源、纳排、样本量、分组/划分）→ 方法与对照 → 评价指标和参考标准 → 主要结果 → 结论。每一步写清"作者做了什么"并给位置。

在这条路线上做两件事，这是第一层的核心：

**标出决策分叉。** 找出作者真正做了选择的地方——选这个数据集而不是那个、这个参考标准、这个对照方法、这个时相、这个划分方式、这个统计量。对每个分叉写：作者的选择；现实中可行的替代做法；这个选择带来的好处与代价；如果换成替代做法，结果大概会往哪个方向变、变多少（这一项一律标为"推断"，并说明推断依据）；论文是否给出了选择的理由。不要把每个细节都当分叉，只保留会影响结论或其适用范围的那些，通常 4–8 个。

**找路线断点。** 检查相邻两步是否真的接得上：声称的缺口是不是实验实际检验的缺口；假设能不能被这个设计检验；评价指标测的是不是结论里说的那个东西（构念是否一致）；结论的范围有没有超出数据和设计。断点往往比单个方法缺陷更致命，因为它意味着实验再干净也回答不了提出的问题。

细节、各类型论文常见的分叉清单和写法示例见 `references/route_reconstruction.md`。

## 第二层：核对证据

为每条核心结论建一行"主张–证据台账"：结论原话或忠实转述（带位置）→ 支撑它的具体图表或数值（带位置）→ 成立条件（人群、数据、参考标准、时相、比较对象）→ 还没有被证明的部分 → 证据强度判断。

每一条陈述都打上来源标签，这是本 skill 最重要的纪律：

- **[原文事实]**：论文报告的观察结果或数值，能指到具体位置。
- **[作者推断]**：作者对结果的解释、机制说法、临床意义、推广范围。
- **[读者推断]**：你自己的分析和推测，未经检验，必须这样标出。
- **[未报告]**：判断所需但论文没有给出的信息（写明查过哪些部分）。

不把猜测当动机：不写"作者为了让结果好看而……"，只写"这个选择会使结果偏向……，论文未说明理由"。不因结果显著就默认可靠，也不因效应小就默认无用；看效应量、区间、一致性界限和统计单位。

找问题时，按 `references/evidence_audit.md` 里的探针逐项过一遍：关键支点测试（拿掉哪一条证据结论就塌）、构念一致性、参考标准、统计单位与独立性、数据泄漏、多重比较与选择性报告、混杂与替代解释、外部验证、正文/表格/图之间的数字一致性（能重算的就重算）。每个问题写成"具体的设计/分析选择 + 在什么条件下会扭曲结果"，例如"测试集与训练集来自同一中心同一扫描仪，因此无法区分模型泛化与站点特异性"，而不是"样本量小"。并标明这个问题是作者在 Limitations 里自己承认的（给位置），还是读者推断的。

问题按严重度分三级：**致命**（动摇主要结论）、**限定**（结论成立但范围需收窄）、**次要**（不改变结论）。最重要的问题放在最前面，不要让二十条小问题淹没一条致命问题。

## 自我反驳：删掉站不住的批评

在写第三层之前，扮演作者为论文辩护：写出最强的反方论证，然后逐条检查自己列的问题——论文是否在补充材料、Limitations 或引用的前作里已经处理过？这个问题在该研究类型的常规标准下是否合理？是否只是"我更喜欢另一种方法"？处理不了的保留，已被回应的删除或降级，并在报告里记下删了什么、为什么。批评也要满足和主张一样的证据标准。同时检查是否只攻击了论证而没质疑前提：这篇论文问的是对的问题吗？

## 第三层：形成下一步方案

把前两层的发现落回读者自己的研究，而不是泛泛地说"未来可以扩大样本"：

- **可以借鉴的**：具体到哪个设计、数据处理或评价做法值得复用，以及复用的前提条件。
- **要避开的**：哪些坑在自己的工作里也会出现，怎么提前防。
- **引用这篇时怎么写**：一句带限定条件、不超出证据的可引用表述，例如"在单中心内部测试集上，X 相比 Y 提高了收缩末期全局应变的一致性"，并注明引用依据的阅读深度。
- **还没被回答的问题**：从路线断点和证据缺口里提炼 1–3 个可检验的问题，每个给出能回答它的最小实验或分析（数据、对照、指标、预期结果的含义）。这些是候选方向，不是既定课题；不要替用户决定研究方向。

如果用户没有说明自己的研究背景，第三层写得通用一些，并在结尾问一句他们想把这篇用在哪里。

## 报告与交付

按 `references/report_template.md` 的结构写报告。用户要求保存或论文较长时，存为 Markdown 文件（默认 `reading/<第一作者>_<年份>_<短标题>_deconstruct.md`，用户另有约定时从其约定），并在对话里给出最关键的三到五条发现和文件路径。语言平实，用连续段落为主，表格只用在主张–证据台账和决策分叉这类确实需要并列比较的地方。

交付时说明：读了什么、没读到什么；哪些数字重算过；哪些判断是读者推断；这是 AI 辅助的单人精读，不等于独立同行评审，关键数字在用于自己稿件前应由用户对照原文核实。

## 与其他 skill 的分工

需要更系统的偏倚/统计谬误清单时，读 `scientific-critical-thinking` 的 `references/common_biases.md` 和 `references/statistical_pitfalls.md`；需要核对 DOI、作者、卷期时用 `citation-management`；要写给编辑的正式审稿意见用 `peer-review`；要跨多篇论文比较和综合用 `literature-review` 或 `academic-deep-research`。本 skill 只负责一篇论文读深、读透、找出问题。
