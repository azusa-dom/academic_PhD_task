## 运行入口

v9 环境文件记录的 docs-figures runtime 为 `/mnt/iusers01/fatpou01/bmh01/f12147zh/csf3-envs/docs-figures/current/`，较新标准库脚本可用 `/mnt/iusers01/fatpou01/bmh01/f12147zh/csf3-envs/cli-anything-tools/current/bin/python`。这些是 CSF3 路径，不是本机路径，也不能据此假定 Claude 已有 SSH 访问。其他环境以任务台账和 Slurm 模板中的显式解释器路径为准。

接续计算任务时依次确认：当前主机和项目目录；输入授权与路径；任务实际解释器及版本；所需模块与包；Slurm 资源及线程；输出位置和单一写入者。做与任务相称的最小检查后再运行，不重新建一个庞大的统一环境。

曾出现 MATLAB 模块的 `libstdc++` 污染 Python 绘图进程：既有单病例任务通过仅在 Python 命令前卸载 MATLAB 模块解决。这是环境隔离问题，不能解释为算法失败。

## 仓库与安装包

本地有 `Supervisor-Skills` 与 `Al-research-SKILLs` 两个仓库。前者提供选题、写作和绘图技能；后者提供 AI 研究工程技能和安装 CLI，不能因为仓库存在就断言所有工程技能都已使用。后者根目录 package.json 为 `ai-research-skills` 1.0.1，安装 CLI 子包为 `@orchestra-research/ai-research-skills` 1.7.2、要求 Node ≥18、依赖 chalk 5.6.2 / inquirer 9.3.8 / ora 8.2.0。这些是本地源文件版本，不是全局安装或最新发布版本证明。

本次交接包不包含 venv、Conda、node_modules、模型权重、MRI/DICOM、密钥、原始稿件全文或数据库，也不执行软件安装。复制的 skills 需要按自己的 `SKILL.md` 单独核对依赖；不自动运行其中脚本。
